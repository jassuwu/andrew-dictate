# andrew dictate — glossary

the domain model. one term, one meaning. if a word isn't here, it doesn't get used in code or docs.

| term | meaning |
|---|---|
| **utterance** | the audio from one press to its release. the atomic unit of the whole app. only you throw one away (`esc`); sleep, the lock, the mic changing and the capture ceiling end it but keep it. |
| **transcript** | raw text produced by the engine for one utterance. never mutated in place. |
| **engine** | the ASR backend that turns audio into a transcript. parakeet via FluidAudio for dictation; whisper via WhisperKit for meetings, or parakeet v3 when it is the meeting model you picked. **code-only term** — every user-facing surface calls it the *speech model*. |
| **cleaner** | the deterministic pass. eight staged transforms, always on, no model. renders speech as writing; never decides you meant something else. |
| **mishearing** | a word in a transcript that is not the word you said. the speech model made it; the cleaner did not. the dictionary, and a learned entry, fix one that comes back. wrong formatting is a different fault, and the cleaner owns it. |
| **agent** | the ai tool you prompt: a coding agent, a chat. the reader the app is made for. it reads a dictation the moment it lands, and a transcript file when you point it at the folder. it understands a sentence that has a mishearing in it, which is why speed comes before accuracy. |
| **lamp** | the glass tube the hud draws while prewarming, recording, and cooling. it comes up dim at the press and lights, with the start chime, on the mic's first audio: lit means the mic is hearing you, not that a key went down. its afterglow is the success signal, which is why failure must cut it short. while a meeting records it keeps a light of its own, following the meeting's phase: lit, flat, quieter than any take and deaf to the room, the ember while the meeting gets ready (until its model is in and the tap has heard the start sound), the attention colour while a problem stands, out with the cool-out at stop, and hidden from screen capture. |
| **pill** | the glass hud style. carries every exceptional message, and the app's few questions about meetings: if the pill is showing, something needs saying or answering. a question gets one quiet glass button that does what the menu item of the same name does, and a click beside it is an answer too. a question waits for a free pill, and gives way to dictation unanswered. a pill about a meeting is kept out of screen capture. |
| **inserter** | puts a transcript into the frontmost app (paste-based, transactional, clipboard-restoring). the sole consumer of a transcript. |
| **delivered** | a dictation whose ⌘V was posted with focus still where we left it. the only completion that counts toward the published latency; the app does not claim the target app accepted the text. |
| **dead press** | a press of the dictation key that ends in neither a delivered dictation nor a pill saying why: silence, an endless lamp, or "restart the app". the trust bar is zero of them, and that includes recovering by itself from anything the mac does underneath (sleep, the lid, displays, bluetooth, a call taking the mic). |
| **press record** | how one press of the dictation key ended — delivered, left on the pasteboard, heard nothing, refused and why… — with the mic and how it is attached, samples, peak level and stage timings. never a word of what was said; a word count at most. exactly one per press, whatever the ending: it is the evidence a dead press leaves. |
| **press log** | the press records: one notice-level line each in the unified log, and the last 200 in a 0600 file next to the dictation archive, wiped with your history. `copy diagnostics` hands over the last 50. |
| **hud** | the single floating panel (nonactivating NSPanel). shows recording state and results. the only persistent ui. |
| **streaming** | the engine transcribes while you are still talking, so key-up only finishes the tail. invisible: the text still lands once, at key-up, in one paste, and must match what the whole utterance would have produced. never live typing into the target app. |
| **learned entry** | a dictionary entry the app added itself: you made the same sound-alike swap to text we inserted twice. announced once, undone in one click, owned by you like any other entry. |
| **prewarm** | loading + compiling the engine at launch so the hotkey path never touches model loading. |
| **wake** | a throwaway pass through the engine at key-down, so it is warm at key-up. prewarm loads the engine; wake keeps it from idling. skipped while the engine is busy, so it never stands in front of an utterance. |
| **onboarding** | the only place that asks macOS for permissions. first run: two grants + model download, ending with a working hotkey — and it returns whenever the app can no longer do its job. |
| **setup** | whether the app can dictate *right now*: both grants live, model ready. a fact about the present, re-asked; never a stored claim that it once succeeded. |
| **capture** | the mic as the app holds it between presses: one `AVAudioEngine` on its own queue, bound to the default input, reused press after press until the hardware changes, then replaced — never rebuilt in place. |
| **mic handoff** | a meeting moving to another mic while it records, because the default input changed or its mic went away: once the hardware has settled, a new tap and mic come up beside the old ones and take over on their first audio; one that never delivers is dropped after five seconds. silent, and the meeting's clock carries on; more than a second with nothing from either side is a gap in the file. |
| **pre-roll** | optional ~300ms rolling in-memory mic buffer (user toggle) so the first word is never clipped. discarded continuously; never written anywhere. |
| **mic turn** | the machine's hold on the capture for one utterance: started at key-down, stopped at its end. one capture serves many mic turns. |
| **chord** | another key going down while the dictation key is held. inside the first second it is a shortcut (fn+arrow) and the utterance is thrown away quietly; after that, or over a locked recording, it ends the utterance and keeps it. |
| **locked recording** | double-tap the dictation key to record hands-free; a single tap ends it and inserts as normal. |
| **capture ceiling** | five minutes of one utterance. the capture stops accepting frames; the take is kept and still inserted. |
| **dictation** | one delivered utterance, kept: raw + inserted text, time, engine, key-up→inserted. your own speech. deleted only by you. |
| **meeting recording** | a local recording of everything the mac plays plus your mic, from `record a meeting`, the reminder's `record` or the meeting shortcut to `stop recording`. no app is picked (ADR 0049); the file is named after the call app on the mic at the start, or `meeting`. holds other people's words, so it is its own noun with its own rules (ADR 0022): the transcript stays until you delete it, and the audio waits a day by default as kept audio, then goes, unless the transcript came out thin (ADR 0048). |
| **tap** | the Core Audio tap on the whole mac — every process, this app's included. its channel is *them*. it comes up with the mic in one private aggregate device, on the mic's clock. its permission is proved by hearing the start sound, never asked for (ADR 0021); after that silence is never held against it, and only a missed quiet probe or a callback that stops makes it dead, a gap from where the far side was last heard, and rebuilt beside the pair still delivering. a time its buffers' own clock skipped — the lid, a mic gone — is a gap too, over when it is known, and no rebuild. |
| **quiet probe** | a third of a second of 1 khz at -40 dbfs that the app plays into a meeting when the far side has been silent two minutes while something else on the mac plays. the tap hears it if it hears anything: heard, nothing is said; missed, the tap is dead. silence alone is never damage. never transcribed, like the start sound, which is the first probe (ADR 0021). |
| **you / them** | the two channels of a meeting: your mic is *you*, everything the mac plays is *them* — the call, and a video or a notification sound if one plays. each is cut into stretches and read apart, so a line's label is the side it came from, not a guess. the speaker split numbers *them* into `them 1`, `them 2`… when it hears more than one voice. |
| **stretch** | a run of one side's speech, from where silero hears it begin to where it ends, at most 25 s for whisper and 15 s for parakeet, decoded once. one stretch is one live line and one turn in the file. |
| **speaker split** | FluidAudio's diarizer, hearing the far side a minute at a time while the meeting records, so the file can number its voices `them 1`, `them 2`… in the order they first speak. one voice, or audio it could not hear, leaves plain `them`. its models come down with the meeting model. |
| **spool** | the 0600 audio file and its manifest that a meeting writes to while it runs, in application support. once the transcript is written it becomes kept audio, or is deleted then if the setting says `delete at once`. a spool a crash left is transcribed at the next launch and saved `recovered`; one that cannot be read is set aside, never deleted. |
| **live transcript** | the floating glass panel during a meeting: finished stretches, `you` and `them`, as they are decoded, never dimmed or rewritten, and out of every screen capture. the stretches it shows are the transcript, unless the coverage check has the audio read again. |
| **phase** | what a meeting is doing, as the menu's first line, the badge and the lamp all read it: getting ready, recording, a problem, writing it out. one value worked out from the meeting, so the three never tell it differently. `saved` is a moment, not a phase. |
| **problem** | something wrong that a meeting records through rather than ends on: the call unheard, your mic unheard, the audio not saved, the disk nearly full. said on the lamp when it begins and when it clears, the menu's first line and the badge's red `!` until then. one of each kind at most, the worst first; none opens a window. |
| **kept audio** | a meeting's audio after its transcript is written: compressed, both sides still apart, with a label naming its transcript, in the app's private folder at 0600 — never the transcripts folder. kept as long as the setting says — a day by default, seven days, or not at all — then deleted without asking; a thin transcript's is kept until you delete it, or a week once its transcript is gone from where it was written. its history row says so and offers `delete audio now` and `transcribe again with ▸` (ADR 0048). |
| **transcript file** | the markdown file a meeting produces: front matter (who spoke, how many words, whether it is whole and why not), then one paragraph per speaker turn, `[hh:mm:ss] you: …`, with a new one every minute of a long monologue and after a pause of more than 3 s. english when the model translates (whisper large, the default); as spoken when it cannot (turbo, parakeet). written once, and replaced in place only when you have its meeting transcribed again. a `README.md` beside the month folders tells an agent what they are. |
| **hollow transcript** | a transcript file that says `complete` and does not cover what was said: empty, thin, or cut short, with the audio already gone. the meeting bar is zero of them, and zero lost meetings. |
| **coverage check** | at stop, before any audio is deleted: the speech the transcriber cut and read on each side, and how long the spool says the far side was loud, held against the words in the transcript. a transcript that fails it is *thin*, and is read again from the spool before the file is written once; still thin, the file says `complete: false` and why, and the audio is kept. a recovered spool, and a meeting transcribed again, are checked once and not read again. the guard against a hollow transcript (ADR 0048). |
| **meeting record** | how one meeting ended — saved, saved thin, nothing kept and why, the model failed, a recovery and what became of it — with speech seconds and word counts per side, gaps, mic and tap events, problems, decoding counts and the coverage result. never a word of what was said. exactly one per meeting, and one more each time it is transcribed again: it is the evidence a lost meeting or a hollow transcript leaves. the last 200 are kept; `copy diagnostics` hands over 20. |
| **hook** | one executable, run detached after a transcript is saved, with the path as `$1` and the details as json on stdin. the only event is `meeting-saved`, and it runs a second time for a file replaced because its meeting was transcribed again, with `again: true` (`ANDREW_AGAIN=1`). |
| **call watcher** | decides from Core Audio's process objects when a call begins and ends: a call app holding a mic and playing audio for three seconds is a call, and it ends when the app has done neither for 30 s, or 30 s past ten minutes of audio alone. it suggests and never acts: `call in zoom — record it?`, the reminder, once per call with nothing recording, and `call ended — stop recording?` once with a recording running. it runs only while the chosen meeting model is on the mac (ADR 0047). |
| **nudge** | after an hour in which a meeting's tap hears nothing, `still recording?` is asked twice: in a notification with `keep going` / `stop`, and on the pill with `stop`, for whoever has notifications off. the first answer counts and the other is withdrawn. it asks; it never acts. |
| **update check** | the one request the app makes on its own. once a day it sends the running version to dictate.jass.gg and nothing else. never while dictating or recording a meeting. on unless switched off in settings (ADR 0043). |
| **update line** | `update to <x>` in the menu, shown when the update check heard of a newer version. a line and nothing else, no dot on the badge. a brew install runs the upgrade in the background and the line follows it: `updating…`, then `restart to finish`, or `couldn't update — command copied`. a dmg install gets the releases page. |
| **demo** | the scenes on the site where a visitor holds a key and a dictation lands, or presses record and a meeting becomes a file. scripted, never a recording of a real dictation or a real call, and the page says so. the wait between letting go and the text is the app's own measured one, and no number is printed. |
